## Rendering and accessibility decisions

`components/scene/device.tsx` owns the ivory Classic device.
`components/scene/wide-device.tsx` owns the graphite Wide model, including its
sculpted housing, grips, side bumpers, physical D-pad, and A/B buttons.
`lib/device-layout.ts` shares geometry/overlay dimensions between components.
`components/scene/portfolio-scene.tsx` owns lighting, the display plinth,
architectural backdrop, orbit accent, and GSAP camera/device transitions. The
HTML overlay is projected from the device's world coordinates without per-frame
React state changes. GSAP owns Three.js transforms; Framer Motion owns only
screen-content opacity.

`components/portfolio/screen.tsx` and `controls.tsx` share navigation across
both 3D modes, with distinct screen layouts and control arrangements. `hooks/use-navigation.ts` owns one shared input controller; `lib/navigation.ts` owns selection, nested history, and saved reading positions.
`data/portfolio.ts` contains chapter data and structured records;
`components/portfolio/section-content.tsx` renders the section-specific content. Replace placeholders only
with supplied or approved facts.

The scene is dynamically imported, uses no external model/font/image requests,
caps pixel ratio at 1.5, and uses inexpensive procedural materials and geometry.
Reduced-motion mode switches to demand rendering. GSAP tweens and DOM listeners
are cleaned up. WebGL2 capability failure, context loss, and scene render errors
show a clearly labeled graphics-unavailable message and readable chapter
accordions. This is error recovery only, not a selectable flat device mode.
Native HTML buttons, visible focus, a skip link, focus restoration, and scrollable
chapter content remain available in both modes.

This is the first implementation, not a finished personal portfolio. The screen
uses a deliberately compact layout; longer chapters scroll. Real-device touch,
assistive-technology, and performance audits are still future work. No live
contact endpoint, external profile links, CV, audio, or mini-game are included.

## Games and Snake

The main menu now has seven entries: the six portfolio chapters and Games.
`src/data/games.ts` is the game catalog. `components/games/game-library.tsx`
renders the selection screen; `snake-game.tsx` renders the in-device playfield.
The deterministic engine is in `lib/snake.ts`; `hooks/use-snake.ts` owns its
fixed 160ms interval and safe best-score persistence. No game dependencies were added.

- Move with arrows, WASD, either device's D-pad or a swipe
  across the board. Food adds 10 points. Walls and body collisions end the round.
- Enter, Space, P, or the device A button start/pause/resume; on-screen buttons
  also provide Start/Restart and Pause/Resume. During Snake, the keyboard A key
  means Left (WASD); the physical A button retains play/pause behavior.
- B, Escape, Backspace, or Games return to the game library. Home returns to the
  main menu. Tab keeps normal access to semantic buttons.
- Switching devices, leaving the experience's focus, hiding the tab, or losing
  window focus pauses play. Switching devices preserves the round; resume when ready.
- Best score is stored under `mustafa-portfolio.snake.best.v1`. If storage is
  blocked, the game remains playable and retains best score for the current session.
- The game has no decorative movement or animation requirement. Movement stays
  responsive with reduced motion. Touch controls remain outside the playfield.

The interval exists only while Snake is open and running. Closing the game,
pausing, or unmounting clears it; game visibility/blur listeners are removed
on exit. All keyboard input uses the existing single controller.

Run `node --test tests/*.test.mjs` (Node 22.18+) for engine and navigation
regressions: scoring/growth, turn buffering, reverse prevention, wall/self
collisions, vacating tails, pause/restart, full boards, storage errors, and

## Breakout

Breakout joins Snake in the catalog at `src/data/games.ts`. Both games share
`components/games/arcade-ui.tsx` and the same device screen, Back/Home behavior,
focus restoration, and reduced-motion-compatible presentation.

Breakout has 28 bricks, three lives, 10 points per brick, wall/paddle/brick
collisions, deliberate serves after a lost life, and win/game-over states.
Use Left/Right or A/D, hold the device buttons, or point/drag across the board
with a mouse, trackpad, or touch. Pointer coordinates are converted through the
projected screen transform. Up/Down have no Breakout action. Enter, Space, P,
or device A launches/pauses/resumes. Restart resets the round and waits for a
new launch; Games/B/Escape return to the library, and Home returns to the menu.
Switching device mode or losing focus pauses play without resetting the round.

`lib/breakout.ts` contains deterministic 120Hz fixed-step physics. Elapsed time
is capped after stalls, paddle speed is bounded, and paddle contact changes the
rebound angle without increasing ball speed. `hooks/use-breakout.ts` owns the
animation frame, held inputs, and visibility listeners. Closing/pausing cancels
the frame; exiting removes listeners and clears inputs. SVG ball/paddle updates
avoid per-frame React rendering of the portfolio. There are no extra effects
or dependencies, and reduced motion does not slow the game physics.

`tests/breakout.test.mjs` covers collision faces, score, lives, win/game-over,
pause/resume, restart, bounded paddle movement, frame-rate equivalence, and
navigation back to the library. Run all 29 regression tests with
`node --test tests/*.test.mjs`, then lint, typecheck, and production build.


## Mobile framing and touch layout

The mobile intro, device stage, and caption use normal document flow. Both modes share a stable stage height so switching does not move the footer.
Classic fits vertically and Wide fits horizontally inside that same scene, even
when the phone is upright. The 3D group and HTML screen/control plane share the same
projection and fit bounds. Mobile framing is front-facing; desktop framing is
unchanged. Screen text compensates for the final device scale rather than the
mode-transition animation.

The former mobile toolbar has been removed, including its reserved space.
Use the built-in D-pad, A/B/Home controls, direct screen taps/scrolling, and the
existing keyboard bindings. Hardware touch targets extend around their visible
buttons; diagonal D-pad target boundaries avoid overlap. The small Wide display
omits redundant screen chrome and duplicate game-overlay actions, retaining
the game action bar. Long content and menus scroll within the display.

The viewport supports safe-area insets on all four edges without disabling
browser zoom or requiring an orientation change. Responsive checks cover
320px, 390px, 430px, and landscape phone widths, plus desktop framing.


The dedicated `components/portfolio/footer.tsx` contains keyboard hints, edition,
and role/location text. Hint labels wrap as complete pairs. Its position is
independent of the selected device; a flex page shell keeps it at the bottom
when content is shorter than the viewport. Mobile stage height is shared by
both modes, and scene animation only transforms the hardware and its projected
screen/control plane, never the footer.
